# Ubuntu 拼音输入法需求与开发规划

项目名称：**NovaPinyin**。GitHub 仓库为 [`pyaude/nova-pinyin`](https://github.com/pyaude/nova-pinyin)。

文档状态：需求评审后的基线；v0.2 已预发布，用户授权继续 v0.3。实际实现与验证状态见 [验证记录](validation.md)，后端选择见 [技术决策](backend-decision.md)，v0.3 交互与边界见 [高级输入](advanced-input.md)。
评审日期：2026-10-05。

本文区分产品要求、建议实现和待验证事项。版本号表示交付顺序，不代表已实现或已承诺的发布日期。接口与数据库示例用于说明设计约束，不是已经存在的代码。

## 1. 评审结论与本次修订

复用 Fcitx5、采用成熟拼音引擎、本地保存用户数据的方向合理。原文主要问题是产品要求与长期愿景混合、技术边界过于理想化、各处版本范围不一致，以及“易用”缺少可检查的交付标准。

| 原文问题 | 修订处理 |
| --- | --- |
| “对标搜狗”没有具体衡量标准 | 首先面向 Ubuntu 中文日常输入，定义安装、输入、设置、恢复和兼容要求；搜狗仅作为交互参考 |
| 将 libpinyin 视为只负责候选生成的库 | 它还提供整句解码、候选选择约束和学习能力；先验证适配成本，再确定学习职责 |
| 默认认为 Fcitx5 足以保证 Wayland 兼容 | 按桌面、会话、工具包及应用后端分别验证，优先解决 GNOME 桌面集成 |
| 排序后仍按候选下标回传引擎 | 使用候选标识、输入修订号、消费范围与后端选择映射，避免选错词 |
| `gongchang changshu` 候选包含“工厂参数” | “参数”读 `can shu`，不能作为该输入的精确候选；修正专业词库读音 |
| MVP 既称“能日常使用”，又把基本设置、句子输入延后 | v0.1 提供基础句子组合与现有设置界面；v0.2 再完善词库及高级输入 |
| 把应用识别、编辑器上下文、项目路径视为必然可获得 | 这些能力设为可缺省的提示；项目路径需用户指定或未来编辑器集成 |
| AI 延迟和“轻松替换所有依赖”作为无条件结论 | 改为性能目标、验证门槛、可取消的异步任务和有成本的适配边界 |
| 重复的阶段计划互相冲突 | 合并为一份路线图、一份 MVP 验收表和一份后续任务清单 |

技术核验依据见第 15 节。下文中的架构、默认交互和验收阈值是本项目的建议设计，不是上游项目对本产品的保证。

## 2. 产品目标与范围

### 2.1 目标用户与使用场景

首批用户是使用 Ubuntu 桌面的中文用户，覆盖聊天、浏览器表单、办公文档，以及终端和编辑器中的中文输入。专业用户可在后续版本启用领域词库；开发者补全作为独立的可选能力。

核心目标按优先级排序：

1. 安装后能按清晰的中文引导启用，重登录后仍可使用。
2. 全拼、选词、句子组合、中英文切换和标点行为稳定且可预期。
3. 常用词随选择逐步适应用户，重启后保留学习结果。
4. 基础设置容易找到，配置出错和数据写入失败时仍能输入。
5. 默认离线，不采集完整输入历史，用户可关闭学习、清空个人词条；v0.2 提供导出。
6. 后续支持专业词库、上下文排序和明确触发的补全能力。

用发行版自带的 Fcitx5 拼音建立体验和性能基线。新方案应能解释相对于现有方案的改善；首版不承诺达到商业输入法的整体词库规模、纠错质量或全应用兼容水平。

### 2.2 v0.1 的“易用”要求

- 提供 `.deb`、中文安装说明、首次启用说明、故障排查及卸载/恢复原输入法说明。
- 复用 Fcitx5 配置工具与引擎配置元数据，提供中文标签、候选页大小、中英文切换键、标点模式、学习开关及恢复默认设置。
- 提供清空个人学习数据的明确入口和二次确认；清空包含项目数据与后端学习数据。
- 模式状态清晰可见，基础输入不依赖云服务或下载模型。
- 不要求用户编译源码或手工编辑多个环境文件；需要注销或额外桌面组件时说明原因和操作步骤。
- 安装包不擅自覆盖用户的会话配置、快捷键或移除其他输入法；启用过程由用户执行。

v0.1 不开发独立 GUI 配置中心，但基础设置必须可用。

## 3. 平台与兼容边界

### 3.1 首批支持目标

| 环境 | 规划级别 | 发布要求 |
| --- | --- | --- |
| Ubuntu 24.04 LTS、amd64、GNOME Wayland | 首版主目标 | 完成安装引导及核心应用验收 |
| Ubuntu 24.04 LTS、GNOME Xorg | 兼容目标 | 独立验证，不把它作为 Wayland 故障的唯一解决办法 |
| Ubuntu 26.04 LTS、amd64、默认 GNOME 会话 | 同期验证目标 | 记录实际版本与差异，通过矩阵后才列为正式支持 |
| KDE Plasma、其他发行版、arm64 | 后续目标 | 不作为 v0.1 发布阻塞项 |

截至评审日，Ubuntu 26.04 LTS 已发布，不能再按未来发行版描述。仍以 24.04 为首版开发基线，26.04 使用独立构建和测试环境。[Ubuntu 官方发布目录](https://releases.ubuntu.com/26.04/)

### 3.2 Wayland 的实际约束

Fcitx5 提供前端和工具包集成，但最终输入链路还取决于合成器、应用后端和桌面设置。GNOME 与 Fcitx5 的集成、候选窗定位以及 shell 界面输入存在额外约束；需要验证 IBus 前端、GTK/Qt 输入模块和可选的 Kimpanel 集成。[Fcitx5 Wayland 官方说明](https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland/en)

执行要求：

- 区分原生 Wayland、XWayland 和 Xorg；“在 Wayland 桌面启动”不等于应用使用原生 Wayland。
- Chromium/Electron 的参数随版本变化，安装说明只发布实测方案，不提供一组适用于所有应用的固定启动参数。
- 环境变量按会话与工具包设置，不能无条件全局设置 `GTK_IM_MODULE` 等变量。
- Snap/Flatpak 应用单列验证；宿主机装有输入模块不代表沙箱应用一定能访问。
- 记录候选窗位置、多屏、缩放、焦点切换以及桌面搜索框的结果；未通过的组合明确列为限制。

必须测试 Firefox（包含 Ubuntu 常见的 Snap 安装）、Chromium/Chrome、VS Code、GNOME Terminal、LibreOffice，以及最小 GTK3/GTK4、Qt5/Qt6 文本输入程序。矩阵记录操作系统、桌面、Fcitx5、工具包、应用版本、包来源和应用实际后端。

## 4. 技术路线与验证门槛

### 4.1 基础技术栈

| 项目 | 建议选择 | 边界 |
| --- | --- | --- |
| 输入法框架 | Fcitx5 | 复用按键分发、输入上下文、preedit、候选 UI、配置和前端 |
| 拼音后端 | 优先验证 libpinyin | 技术验证通过后确定；LibIME 作为对照方案 |
| 核心语言 / 构建 | C++20 / CMake / Ninja | 在各目标发行版的编译器及开发包上验证 |
| 项目学习存储 | SQLite3 | 保存项目拥有的词条与统计，不替代后端模型文件 |
| 配置 | Fcitx5 配置体系 | 避免再维护一套重复的 `config.json` |
| 测试 | CTest + GoogleTest | 测试依赖不进入运行时安装包 |
| 日志 | 优先复用 Fcitx5 日志设施 | 默认不输出输入内容；确有需要再引入 spdlog |
| 扩展格式 | UTF-8 TSV；后续按需 JSON | 不为首版引入无用途的序列化依赖 |

OpenCC 在简繁转换阶段按需引入。ICU、ONNX Runtime、SentencePiece、protobuf、gRPC 等不是首版默认依赖。

### 4.2 先评估现有引擎，再决定独立开发范围

Fcitx5 官方中文插件中的拼音引擎链接的是 `LibIME::Pinyin`，并非 libpinyin。其模块构建、配置与安装可以参考，但不能把代码直接视为 libpinyin 的集成样例。[官方拼音模块构建文件](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/im/pinyin/CMakeLists.txt)

libpinyin 的公开接口包含解析、整句推测、带偏移的候选选择、词条导入和学习保存；它不是无状态的“拼音转候选列表”接口。[libpinyin 接口定义](https://github.com/libpinyin/libpinyin/blob/main/src/pinyin.h)

Phase 0 必须回答：

1. 目标 Ubuntu 仓库中的开发包、运行库与语言模型数据能否完整离线安装？记录具体版本、数据路径及依赖。
2. 全拼、分词歧义、短句、逐段选择、撤销选择和自定义词条是否满足首版需求？
3. 能否保留后端选择约束，并安全地合并、重排外部候选？
4. 多个输入上下文怎样共享词库而隔离输入状态？后端对象的线程约束是什么？
5. 与原版 Fcitx5 拼音/LibIME 相比，效果、性能和开发成本如何？
6. 是否通过 GNOME Wayland 的安装、候选显示和真实应用提交验证？

验证结论写成架构决策记录，再冻结后端。若扩展现有 Fcitx5 拼音即可满足目标，优先评估该方案；若保留独立引擎，明确原因。首版只维护一个生产后端。

### 4.3 发布前的授权与数据来源

libpinyin 头文件标注 GPL-3.0-or-later，不能默认认为项目可按任意宽松许可证发布。[上游许可证声明](https://github.com/libpinyin/libpinyin/blob/main/src/pinyin.h)

Phase 0 建立依赖、词库、语言模型、未来 AI 模型的来源与许可证清单，并确定相容的项目许可证和再分发方式。代码许可与词库/模型许可分别记录；不复制商业输入法的私有词库、皮肤或其他未经授权的资源。

## 5. 架构与职责

```text
桌面应用（GTK / Qt / Electron / Terminal）
                   │
                   ▼
Fcitx5：前端、按键、焦点、配置、preedit、候选 UI
                   │
                   ▼
NovaPinyin Addon：生命周期、事件转换、每个输入上下文的状态
                   │
                   ▼
Core Session：组合输入、候选快照、选择与提交策略
        │                  │                  │
        ▼                  ▼                  ▼
PinyinBackend        Dictionary/Ranker     LearningStore
        │                  │                  │
        ▼                  ▼                  ▼
libpinyin 或 LibIME   本地词库/统计快照        SQLite
                     （后续：可选上下文/AI）
```

- Addon 实现 Fcitx5 `InputMethodEngine` 及配置、激活、重置等生命周期接口。Core 不依赖 Fcitx5 类型。[官方引擎接口](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx/inputmethodengine.h)
- 一个 Fcitx5 输入上下文对应一份组合状态；不能用全局单例保存当前拼音。上下文可能对应窗口或文本框，不等同于整个应用。[官方 InputContext 定义](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx/inputcontext.h)
- 拼音后端负责解析、解码、选择约束和后端原生学习；项目层负责额外词条、个性化提升、配置与产品交互。
- 候选生成和展示排序在项目接口层分离，但承认后端的语言模型已经参与候选生成和排序；不能通过重排恢复根本没有生成的词条。
- 第三方 API 封装在适配器中。替换后端仍需重新验证编辑、偏移、词条导入、学习和数据迁移，不承诺零成本替换。
- MVP 只拆出 Addon、Core、后端适配器及存储边界，不提前建设通用插件平台。

## 6. 组合输入、候选与按键语义

### 6.1 状态与候选契约

输入模式与组合状态分开：模式为中文/英文；组合状态为 Idle/Composing。数字和符号是输入内容类型，不必作为独立模式。部分已选词是 Composing 中的结构化状态。

Core 请求至少包含：会话标识、单调递增的输入修订号、原始拼音、光标、已选片段、输入模式及隐私策略。应用标识、周围文本是可选提示，缺失时使用通用策略。

候选至少包含以下信息：

| 字段 | 用途 |
| --- | --- |
| `candidate_id` | 当前修订号内稳定的选择标识，不是 UI 下标 |
| `revision` | 关联生成它的输入版本；过期选择必须拒绝并刷新 |
| `text` / `reading` | 提交文字与规范化读音，二者分别保存 |
| `source` / `backend_selection` | 来源及适配器持有的选择映射；不向 Core 暴露后端裸指针 |
| `input_begin` / `input_end` | 消费的原始输入范围，规定为 ASCII 拼音字节偏移 |
| `kind` | 整段、局部词条、原文或后续预测候选 |
| `backend_rank` / `features` | 原始顺序和可选特征；不假定存在统一概率分数 |

后端的音节偏移与 Core 的原始输入偏移由适配器转换。汉字使用 UTF-8 存储，显示光标/删除操作按所需字符单位转换，不能把 UTF-8 字节偏移当成字符位置。

后端接口需要覆盖：创建/重置会话、更新完整组合状态、获取候选快照、按标识选择、撤销选择、提交后学习及保存。选择返回“新的组合状态/剩余输入/待提交文字”，不能只返回 `void`。所有操作有失败结果和回退路径。

排序及去重后，数字键和鼠标选择必须解析为同一候选标识。外部词库候选必须有明确消费范围和后端约束适配；未实现这些能力时只允许完整覆盖当前输入的词条整段提交。

### 6.2 v0.1 默认交互

| 操作 | Idle / 英文模式 | 中文 Composing |
| --- | --- | --- |
| `a-z` | 中文模式开始组合；英文模式透传 | 在光标位置编辑拼音并刷新候选 |
| `'` | Idle 时作为普通字符处理 | 作为音节分隔符，支持 `xi'an` 等歧义输入 |
| `v` | 英文模式透传 | 按约定表示 `ü`，如 `lv`；在提示及词库规则中统一说明 |
| Space | 透传空格 | 选择当前页第一个候选；局部候选保留未选部分；无候选则提交原文 |
| `1-9` | 透传数字 | 选择当前页对应候选；无候选时提交原文再透传数字；不存在的页内编号不选词、不提交 |
| Enter | 透传 | 提交当前 preedit 的已选文字与未选原文，清空组合；该次 Enter 不继续换行或执行命令 |
| Esc | 透传 | 取消组合，不提交、不学习 |
| Backspace / Delete | 透传 | 删除光标附近的未选输入；在已选片段边界先撤销该片段选择；组合为空后回到 Idle |
| Left / Right、Home / End | 透传 | 在组合范围内移动光标，必要时撤销受编辑影响的选择 |
| PageUp / PageDown | 透传 | 候选翻页，边界不循环，不改变组合输入 |
| 常用标点 | 按模式输出 | 先完成当前组合，再输出标点；无候选时保留原文，不丢输入 |
| Ctrl / Alt / Super 组合键 | 交由框架或应用处理 | 除已配置输入法快捷键外透传，不吞掉复制、粘贴和应用操作 |

补充约束：

- Fcitx5 管理输入法启停与组切换；引擎内中英文切换默认采用单独按下并释放 Shift，可在现有设置界面修改。Shift 参与其他按键组合时不触发切换。
- Composing 切到英文时先提交已选文字与未选原文，避免默默丢字；切换快捷键与框架全局配置有冲突时提示并允许更改。
- 支持基础词组、短句和逐段选词；长句质量优化放到 v0.2。超过建议初始上限 256 个原始输入字节时，保留已有组合并给出提示，不静默截断。
- 按键按下/释放、连按、自动重复必须分别处理，保证一次选择只提交一次。
- 焦点移出时隐藏候选并使后台结果失效，未完成组合仅保留在原上下文；恢复原上下文时可恢复。框架要求 reset/deactivate 或上下文销毁时清空未完成组合，不向新焦点提交。前端明确要求的失焦提交需单独适配和测试。
- 候选窗口显示与应用内 preedit 使用框架能力；不支持应用内 preedit 的组合，使用框架提示区回退。
- 默认半角数字/英文；中文模式映射常用中文标点，英文模式透传。终端默认半角标点，用户可覆盖；应用提示缺失时采用通用设置。

完整标点表、引号配对规则与逐段编辑行为在实现前写入交互测试用例，不能依赖某个后端的偶然默认行为。

## 7. 候选排序与用户学习

### 7.1 排序策略

首版保留后端顺序，增加有上限的个人词条提升，不建立多级复杂 Ranker 管线。相同分数采用确定性的原始顺序作为 tie-break，避免候选在相同输入下跳动。

后续可采用如下启发式，参数通过固定语料与用户体验评测调整：

```text
score = backend_rank_prior
      + bounded_user_boost
      + bounded_domain_boost
      + optional_context_boost
```

各来源的频次、词条长度、后端分数不具备天然相同量纲。使用排名先验、`log1p`、衰减和归一化等可解释特征，避免原始频次线性相加，也避免与后端学习重复累加相同信号。不存在的特征记为缺失，而非伪造概率。

精确拼音、模糊音、纠错和预测候选分别标记。MVP 只做精确输入；如 `gongchangchangshu` 可对应“工厂常数”，而“工厂参数”是不同读音，不能通过提高领域权重变成精确候选。

### 7.2 学习职责

- 用户实际提交且对应候选选择的文字才产生学习事件；Esc、原文 Enter、失焦取消和过期异步结果不学习。
- libpinyin 等后端的原生学习由适配器管理；SQLite 保存项目的可导出词条、选择次数与最近使用时间。Phase 0 明确哪些信号用于重排，哪些只由后端使用。
- 学习只保存所需的词条与规范化读音，不默认保存整段历史、窗口标题或周围文本。v0.1 不保存按应用分类的统计。
- 不承诺任意词“选择几次后必为首选”；对固定种子数据规定可重复的适应性测试。
- 用户学习词条应能再次进入候选集合，而不是只有统计但无法被召回。通过后端词条导入或项目词条查找实现，验证重启后依然有效。
- 关闭学习同时关闭项目与后端的新学习写入；已有词条仍可使用。进入隐私模式时禁用学习、个性化/预测及上下文采集，使用基础模型。

### 7.3 SQLite 初步设计

```sql
CREATE TABLE user_phrase (
    reading TEXT NOT NULL,
    phrase TEXT NOT NULL,
    selection_count INTEGER NOT NULL DEFAULT 0 CHECK (selection_count >= 0),
    last_used INTEGER NOT NULL,
    PRIMARY KEY (reading, phrase)
);
PRAGMA user_version = 1;
```

`reading` 为小写、无声调、单空格分隔的完整音节，`ü` 规范化为 `v`；`last_used` 为 UTC Unix 秒。多音词允许同一文字有不同读音行。界面显示时间再按用户时区转换。

采用参数化 SQL、事务批量写入和带版本的迁移。先更新内存统计，再由单一写入工作线程持久化；主事件循环不做数据库查询或提交。需要删除学习数据时，先暂停生产学习事件并排空/取消旧写入，再清除内存、SQLite 与后端用户模型，防止被旧任务写回。

建议合并写入间隔不超过 2 秒，正常退出尝试在 1 秒预算内完成已排队写入。进程崩溃可能丢失尚未写入的统计，不能宣称学习零丢失。磁盘满、权限不足、数据库锁定或损坏时继续基础输入，给出可操作的提示；不得静默删除原始数据库。

## 8. 词库与扩展格式

v0.1 包含授权明确的基础数据和少量固定测试词条；用户安装多个领域词库、导入导出与管理能力放到 v0.2。

项目自定义交换格式暂定为 UTF-8 TSV，字段为“文字、规范化读音、非负词库权重”，用制表符分隔。它不等同于 libpinyin、LibIME 的原生词库格式，适配器负责转换。

```text
# novapinyin-dict-v1
掩膜版载台	yan mo ban zai tai	100
调平调焦	tiao ping tiao jiao	100
对准	dui zhun	100
激光干涉仪	ji guang gan she yi	100
工厂常数	gong chang chang shu	100
```

- 权重是词库内部的相对先验，不是选择次数或概率。
- 验证 UTF-8、字段数量、读音合法性、行长、文件大小、重复项及合理的条目上限；错误给出行号。
- 多音词显式提供不同读音，不能仅靠自动汉字转拼音判断。
- 默认只接受完整词条的完整读音；简拼、模糊音和别名按后续显式规则实现。
- 导入先验证，成功后原子替换；失败保留原数据。去重使用文字、读音和消费范围，并保留选择所需的来源信息。
- 每个分发词库包含名称、版本、来源、许可证与校验信息。导出只包含用户词条，不意外导出第三方词库或输入历史。

v0.2 模糊音按用户选择启用，覆盖 `z/zh`、`c/ch`、`s/sh`、`n/l`、`an/ang`、`en/eng`、`in/ing`；不同规则独立配置。纠错如 `nihap → nihao` 需限制搜索规模，保留原文与精确候选优先，不能无条件自动改写。双拼优先复用后端方案；具体首批方案根据试用反馈确定。

## 9. 上下文、开发者模式与 AI

### 9.1 上下文能力（v0.3）

优先使用客户端明确提供的应用标识及周围文本能力。Fcitx5 的 `program()` 可以为空，周围文本也不是每个文本框都提供。[官方 InputContext API](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx/inputcontext.h)

上下文默认不采集，后续由用户明确开启。开启后只在内存保留有界的最近文本；跨输入上下文、重置或进入敏感字段立即清除。客户端无法提供时，可在同一会话内使用本引擎刚提交的有限文本作为弱提示，但不能假设它等于当前光标前的真实文档。上下文缺失不影响全拼和学习功能。

应用类别是可覆盖的提示，不用于强制自动切换模式。输入法无法仅靠 Wayland 全局读取编辑器文件内容、工作目录或语义信息。

### 9.2 开发者模式（v0.3）

采用用户显式进入的补全模式或专门触发键，保留普通英文输入、Shell 历史和编辑器原生补全。`nihao` 与英文串存在歧义，不能仅靠字母判断用户意图。

例如在专用补全模式中输入 `git che`，可显示 `git checkout`、`git cherry-pick`。该模式需要单独定义空格的捕获、候选消费范围和退出方式；普通拼音模式中的 Space 仍选词。`cmake ta` 到 `target_link_libraries` 属于补全规则，不是拼音转换。

候选只提交文字，绝不自动执行 Shell 命令。项目词库需要用户选择目录并显式索引；默认排除凭证、隐藏敏感文件、二进制与超大文件，遵循配置的忽略规则。不得声称输入法能自动知道 VS Code 当前项目；自动绑定需未来的编辑器集成。

### 9.3 AI 能力（v0.4，实验性）

先评估 N-gram/规则基线，再评估小型本地模型。FastText 是一种可选模型工具，ONNX Runtime 是运行时，不能把名称本身视为已验证的候选重排方案。

AI 重排、下一短语预测、句子补全和语义纠错分别评测。精确候选重排不能任意改变读音或悄悄替换用户文字；纠错与补全单独标记，并经选择才提交。

流程：先立即显示传统候选，再对有界候选集合做可取消的后台推理。初步可评估 Top 20，但不假定 libpinyin 总能生成 100 个候选。AI 结果仅在会话、焦点和修订号仍匹配时使用；用户已经翻页或开始选择后冻结当前候选顺序，避免数字选词目标变化。

目标硬件上的附加推理 P95 预算暂定 10 ms，必须实测；超时或失败直接使用传统结果。模型大小、内存、启动成本及输入质量改善通过评测后才能进入默认安装包。

远程 AI、企业词库同步、Git/HTTP 同步属于更后期可选能力。未来开启远程服务时，单独说明端点、发送字段和保留策略，默认不发送上下文或个人词库；禁止在输入事件路径等待网络。

## 10. 隐私、目录与恢复

### 10.1 默认数据策略

- v0.1 无云输入、遥测或完整输入历史；运行时基础输入不需要网络。
- 密码、Sensitive 或客户端禁用输入法的字段遵守能力提示：密码/禁用字段使用直接输入，敏感字段关闭学习、个性化、上下文及预测。客户端并非总能正确标记敏感文本，提供手动隐私模式补充。[官方能力标志](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx-utils/capabilityflags.h)
- 日志只记录模块状态、错误码、耗时及计数；拼音、提交文字、上下文和文件路径等默认不记录。诊断导出需预览并检查脱敏。
- 用户目录仅本人可访问，建议目录 `0700`、个人数据文件 `0600`。目录权限不等于静态加密，不宣称能防止同用户恶意软件读取。
- 清空学习数据包含后端模型、SQLite、内存与相关缓存；配置重置与数据清空是两个独立操作。
- 普通卸载保留个人数据，说明如何显式清理并恢复之前使用的输入框架。

### 10.2 遵循 XDG 目录

以下为环境变量未设置时的默认位置；实现必须优先读取 XDG 变量，缓存不能与需要备份的数据混放。[XDG 官方规范](https://specifications.freedesktop.org/basedir/latest/)

```text
配置：$XDG_CONFIG_HOME/fcitx5/conf/novapinyin.conf
      默认 ~/.config/fcitx5/conf/novapinyin.conf
数据：$XDG_DATA_HOME/novapinyin/
      默认 ~/.local/share/novapinyin/
      user.db、backend/、dictionaries/、必要的本地模型
缓存：$XDG_CACHE_HOME/novapinyin/
      默认 ~/.cache/novapinyin/
```

后端原生学习数据存于 `backend/` 并参与备份和清空。最终目录与 Fcitx5 标准路径助手在 Phase 0 确认。配置解析失败时回退默认值并提示；迁移失败保留原文件与备份，不阻断基础输入。

## 11. 性能与线程模型

### 11.1 测量目标

先确定一台公开 CPU、内存、系统和软件版本的普通 amd64 测试机器，记录输入语料、词库规模、构建类型、预热和负载。以下是待验证目标，不是测量结果。

| 指标 | 初步目标 | 测量口径 |
| --- | --- | --- |
| 热状态按键响应 | P50 < 5 ms，P95 < 15 ms，P99 < 30 ms | Addon 收到按键到向 Fcitx5 发布候选/preedit 更新，不包括合成器绘制 |
| 前台卡顿 | 标准测试中无超过 50 ms 的单次处理 | 记录所有超预算事件；不承诺操作系统调度下绝对最坏时延 |
| 候选稳定性 | 选择开始后当前候选顺序不变化 | 连按、翻页、慢任务完成同时发生时检查 |
| 启动 / 内存 | Phase 0 测量并确定预算 | 冷启动首次可输入、稳态及词库加载峰值，分别报告 |

实际屏幕显示延迟用图形会话端到端测试另测。不能把事件处理耗时直接当作用户看到候选的耗时。

### 11.2 线程约束

- Fcitx5 主事件循环处理事件、组合状态和 UI 更新，不等待网络、模型加载、磁盘写入或词库导入。
- 热路径使用只读词库/学习快照；字典加载和数据库写入在后台进行，完成后安全发布新快照。
- 对 libpinyin/LibIME 不假定线程安全；同一会话及共享可变后端上下文明确串行所有权。若生成候选超预算，通过专用工作线程排队并回传快照，不能简单把共享对象并发调用。
- 后台任务携带会话、修订号和取消信息；结果在主事件循环验证后更新 UI，不从工作线程访问已销毁的 InputContext。
- 队列有容量上限，重复输入任务可合并或取消；学习事件不得无声丢弃。持久化不可用时内存缓存有界并明确提示。

## 13. 测试、开发与打包

### 13.1 测试体系

- 单元测试验证拼音规范化、候选映射/消费范围、排序稳定性、词条召回、学习边界、配置解析及数据库迁移。
- Core/后端集成测试输入事件序列，检查组合状态、候选、实际提交与重启数据；精确候选位置只对固定词库和版本设断言。
- 使用 Fake Backend 测试规则和 A/B 学习，使用真实后端固定数据测试召回；不硬编码未经确认的次要候选“拟好/你号”。
- 覆盖组合为空、无合法拼音、超长输入、分隔符、逐段选择撤销、鼠标与数字混合、焦点切换、重复键、异步过期及上下文销毁。
- 故障测试覆盖磁盘满、权限错误、数据库锁定/损坏、加载失败、迁移失败和异常退出；验证基础输入仍可继续。
- 隐私测试检查学习开关、手动隐私模式及密码/敏感能力提示，不产生统计、上下文或日志内容。
- 性能测试使用实际输入长度、词库规模和候选上限；1,000/10,000 候选只作为离线 Ranker 压力测试，不当作每次按键的正常工作负载。
- 图形验收覆盖第 3 节矩阵；无显示的 CI 与 Xvfb 不能代替原生 Wayland/GNOME 验收。

建立版本化语料：常用词、短句、歧义分词、多音词和专业词条。分别报告前 1/前 9 候选命中率、输入后端成本和用户完成句子的操作数；与 Phase 0 基线对照。

### 13.2 开发与项目结构

建议按实际功能逐步建立目录，避免为尚未实现的 AI/云能力创建空模块：

```text
xpinyin/
├── CMakeLists.txt
├── README.md
├── LICENSE
├── docs/                 # 需求、架构决策、安装与测试矩阵
├── src/
│   ├── addon/            # Fcitx5 生命周期、配置、UI 适配
│   ├── core/             # Session、候选契约、交互和排序
│   ├── backend/          # 选定拼音后端的适配器
│   └── storage/          # 学习、SQLite、迁移
├── data/                 # 授权词条、配置元数据、标点
├── packaging/            # Debian 打包
└── tests/                # 单元、集成、语料和性能测试
```

建立工程后采用：

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

当前仓库仅有需求文档，这些命令是未来工程的操作约定，不是当前可运行的构建步骤。

CI 分别在目标 Ubuntu 环境中构建、跑核心及后端测试、做必要的 sanitizer 检查并生成包。图形环境的真实应用验收单独执行，记录结果后才能发布。

### 13.3 打包与安装

`.deb` 包必须包含引擎动态库、Addon 注册、输入法条目、配置元数据及必要数据。按发行版 Multi-Arch 路径与 Fcitx5 CMake 安装变量安装，不能硬编码 `/usr/lib` 或只安装 `.so`。[官方模块安装示例](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/im/pinyin/CMakeLists.txt)

运行时依赖、构建依赖和桌面集成组件分别声明；为 24.04 与 26.04 分别构建并验证，不假设二进制包可跨版本通用。生成包后，安装命令示例为：

```bash
sudo apt install ./novapinyin_0.1.0-1_amd64.deb
```

文件名及版本仅作示例，需替换为实际生成的包。安装后按会话专用说明选择 Fcitx5、添加 NovaPinyin，必要时注销重登录；Debian/Ubuntu 可参考 `im-config` 的启用流程，但完整引导必须经过目标环境实测。[Fcitx5 设置说明](https://www.fcitx-im.org/wiki/Setup_Fcitx_5)

升级保留用户配置和数据，迁移前备份；卸载与重新安装验证不留下损坏注册。新增输入法框架时说明如何回到原框架，避免用户遇到故障后无法输入。

## 14. 下一步任务与待决策项

首先执行 Phase 0，而不是立即建设完整 Ranking/AI 平台。建议任务顺序：

2. 实现最小 Fcitx5 引擎注册、每上下文状态、固定候选和真实应用提交。
3. 验证 GNOME Wayland、XWayland、GTK/Qt 与主要应用输入链路，编写首次启用及恢复说明。
4. 对比 libpinyin 与 LibIME 的候选/逐段选择/编辑/学习/词条导入能力，记录依赖和数据许可，冻结后端决策。
5. 固定候选契约与交互用例，完成真实后端适配及排序后的选择映射。
6. 实现基础设置、中英文切换、标点、隐私模式和关闭学习。
7. 实现用户词条召回、内存学习、后台持久化、清空与恢复。
8. 完成图形兼容矩阵、性能评测和 `.deb` 安装/升级/卸载验收，再发布 v0.1。

待 Phase 0 定稿：最终后端、项目许可证、具体依赖版本、测试硬件及启动/内存预算、GNOME 候选窗集成方案、Ubuntu 26.04 正式支持状态。后续根据试用反馈决定双拼方案、首批专业词库和开发者模式的优先级。

## 15. 技术核验资料

以下为本次评审使用的上游资料；实现时应固定所采用的发行版包版本或提交号，不能把上游最新源码的全部能力假定为 Ubuntu 随附版本的能力。

- [Fcitx5 安装与启用](https://www.fcitx-im.org/wiki/Setup_Fcitx_5)：框架选择、自启动与环境设置。

- [Fcitx5 InputMethodEngine](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx/inputmethodengine.h)：引擎事件和生命周期接口。
- [Fcitx5 InputContext](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx/inputcontext.h)：每客户端上下文、可为空的应用标识和周围文本 API。
- [Fcitx5 CapabilityFlags](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx-utils/capabilityflags.h)：密码、敏感和禁用输入等能力提示。
- [libpinyin 接口与许可声明](https://github.com/libpinyin/libpinyin/blob/main/src/pinyin.h)：候选、偏移、选择、词条导入、学习与保存。

- [Fcitx5 官方拼音模块](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/im/pinyin/CMakeLists.txt)：LibIME 依赖、Addon 构建及注册文件安装。
- [LibIME](https://github.com/fcitx/libime)：对照后端及其词库格式文档。
- [XDG Base Directory 规范](https://specifications.freedesktop.org/basedir/latest/)：配置、持久数据和缓存的环境变量与默认位置。
- [Ubuntu 26.04 官方镜像](https://releases.ubuntu.com/26.04/)：确认该 LTS 已发布。
